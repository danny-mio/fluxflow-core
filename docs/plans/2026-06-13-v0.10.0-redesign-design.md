# FluxFlow v0.10.0 Bezier-Coupled Redesign — Design

**Date:** 2026-06-13
**Branch:** `feature/model-v0.10.0` (all four repos)
**Codename:** `v0.10.0-bezier-coupled`
**Status:** approved by author; pending implementation plan

## Background

A mathematical analysis of v0.10.0 surfaced ~15 distinct quality bottlenecks
across the VAE, SPADE conditioning, and the Flow processor. The three rooted
concerns the author flagged were (a) whether the variational RNG is the right
abstraction given SPADE carries most of the perceptual quality, (b) whether the
z and ctx latent halves have the right relation, and (c) whether the Flow is
intelligent enough to consume text-prompt hints. This redesign addresses 13 of
the 15 findings in a single coordinated change set, keeping the ethos of using
sophisticated formulas (Bezier-cubic activations, KAN-inspired pillars) to
reduce operation count while improving quality, especially at the D=32 latent
target.

The redesign keeps the v0.10.0 version label per directive and replaces v100
modules in place. Cross-package ripple touches all four repos
(fluxflow-core, fluxflow-training, fluxflow-ui, fluxflow-comfyui) on the same
branch. Old v0.10.0 checkpoints are not weight-compatible with the redesign,
but a salvage script reuses ~80% of `flxflow_final.safetensors` and 100% of
`text_encoder.safetensors` and `D_img.safetensors` as a warm start.

## Locked design decisions

The following five decisions were taken during brainstorming and drive every
section below:

1. **Per-token text** end-to-end. `BertTextEncoder` stops mean-pooling and
   returns a `(text_seq, text_mask)` tuple. The Flow's cross-attention becomes
   real attention over real text tokens instead of a length-1 broadcast.
2. **Conditional z/ctx coupling:** `ctx = f(img, z)`. ctx encodes the residual
   z couldn't capture rather than running as an independent parallel pipe.
3. **Full Flow modernization:** 2D axial RoPE, continuous sinusoidal time on a
   separate conditioning channel, dual FiLM (text + time independently),
   widened pillarLayer (D→2D→2D→D), gated `ctx_agg` residual, drop the
   length-1-degenerate `pillar_cross_attn`.
4. **Multi-scale SPADE** with three additive heads (1×1, 3×3, 7×7-dilated) and
   a bounded multiplicative γ = 1 + softplus(scale·raw). Identity at init.
5. **Clean Gaussian z:** wide-range logvar via `WideTrainableBezier`, drop
   tanh after LayerNorm, drop the deterministic `+ pe_content` leak so KL
   pressure actually pulls toward N(0,I).

## VAE — compressor + expander

### Compressor — z path (clean Gaussian)

The 4-stage Bezier conv stack stays. The head is restructured so the
bottleneck is genuinely variational:

```text
latent     = latent_proj(stack_output)
mu         = mu_activation(mu_proj(latent))                 # range ~[-0.5, 0.5]
logvar     = WideTrainableBezier(p0=-8, p1=-2, p2=2, p3=4)  # range ~[-8, 4]
z_sample   = mu + exp(0.5·logvar) · eps                     # reparameterize
z_features = z_sample                                        # exposed to ctx-encoder
z_tokens   = LN(z_sample.flatten(2).transpose(1,2) + sincos_pe)
              # NO + pe_content, NO tanh
```

Why each change matters:

- Wide logvar lets specific channels effectively shut noise off (logvar ≪ 0).
  Critical at D=32 where noise floor was previously O(1) per channel.
- Removing tanh restores the dynamic range of the tails — where edges and
  high-frequency detail live.
- Removing `+ pe_content` makes the bottleneck genuinely variational so KL
  pressure pulls toward the prior the Flow will sample from.

### Compressor — ctx path (conditional on z)

Same conv stack, with z injected at the bottleneck before attention:

```text
ctx_features = ctx_conv_stack(img + coord_channels)         # [B, D, H/16, W/16]
ctx_features = SPADE_inject(ctx_features, z_features)
  # z_proj    = Conv1x1(z_features, D*5) -> Bezier(sig,silu) -> D
  # beta_z    = Conv1x1(z_proj, D)
  # gamma_z   = 1 + softplus(Conv1x1(z_proj, D))
  # ctx_features = gamma_z · GroupNorm(ctx_features) + beta_z
ctx_features = ctx_token_attn(ctx_features.flatten())       # 4 self-attn layers
ctx_tokens   = LN(ctx_features)                             # NO tanh
```

`ctx_attn_heads` becomes `max(2, D // 16)` so head_dim stays ≥ 16 even at
D=32 (today's 8 heads × 4 = noise-only).

### Packed token format

Unchanged at `[B, T+1, 2D]` (z||ctx + HW token). The coupling is purely
encoder-side; the format remains a clean container compatible with existing
pipeline glue.

### Expander — multi-scale SPADE

The `_ResidualUpsampleBlock` replaces single-scale SPADE with three additive
heads plus a bounded multiplicative γ:

```text
shared = Conv3x3(ctx, 128*5) -> Bezier(sig,silu) -> 128
shared = Conv3x3(shared, 128*5) -> Bezier(sig,silu) -> 128   # 2 layers, vs 1 today

beta_low  = Conv1x1(shared, C)                # global / low-frequency
beta_mid  = Conv3x3(shared, C)                # local edges
beta_hi   = Conv3x3(shared, C, dilation=3)    # extended texture
gamma_raw = Conv3x3(shared, C)                # multiplicative

beta  = beta_scale  · (beta_low + beta_mid + beta_hi)
gamma = 1 + softplus(gamma_scale · gamma_raw) - softplus(0)  # exactly 1 at init
out   = gamma · GroupNorm(x) + beta

beta_scale = gamma_scale = nn.Parameter(zeros(1))             # identity at init
```

Cost: ~2.5× FLOPs per SPADE call vs today; decoder total ~+30-40%.
Acceptable at D=32 — and the math gives the redesign its sharpness headroom.

### What stays the same

`_ProgressiveUpscaler` skeleton, `seam_smoother` and `seam_smoother_ctx`,
`to_rgb_conv` chain, the 16×16 transposed conv + 5×5 dilated conv per upscale
step, and the Bezier 5× channel expand idiom (the ethos lever).

### What is removed

`tanh` after LN on z and ctx; `+ pe_content` deterministic leak; the narrow
single-SPADE MLP; the old bounded logvar TrainableBezier.

## Flow processor

### New forward signature

```python
def forward(self, packed, text_embeddings, text_mask, timesteps) -> packed
#                       ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
#                       [B, T_txt, E] + [B, T_txt] bool, not [B, E]
```

`T_txt` defaults to 32 (DistilBERT context cap). Padding/masking handled at
the dataset side.

### Text and time projection (separate channels)

```text
text_seq  = text_proj(text_embeddings)                # [B, T_txt, d_model]
text_cond = text_cond_proj(text_embeddings[:, 0, :])  # [B, d_model] from [CLS]
time_emb  = sinusoidal_embedding(timesteps, d_model)  # continuous, no 1000-bin
time_cond = time_mlp(time_emb)                        # [B, d_model]
```

`text_cond` and `time_cond` are never summed. They feed two separate FiLM
layers per pillar.

### 2D axial Rotary PE

Image tokens get axial 2D rotation: top half of head_dim rotates with
W-position frequencies, bottom half with H-position frequencies. Adjacent
pixels become adjacent in RoPE space; the encoder's 2D structure is preserved.
Text tokens keep 1D RoPE over the text-token index.

### Mask-aware ParallelAttention

`ParallelAttention.forward` gains an optional `attn_mask` argument. The
softmax masks `-inf` at invalid positions before normalisation. Backward
compatible — `attn_mask=None` reproduces today's behaviour.

### Block forward

```text
1. self-attn on img with 2D axial RoPE
2. cross-attn img -> text with separate norm2_q / norm2_kv, mask-aware
3. gate g = sigmoid(img_seq)
4. pillar MLPs first (kept from current v0.10.0 ordering)
5. dual FiLM (text + time independently, additive scales and biases)
6. (REMOVED) pillar_cross_attn — was length-1 degenerate
7. FFN + Bezier-combine on [img_seq | img_p0 | img_p1 | img_p2 | img_p3]
```

### Widened pillarLayer

Today's `pillarLayer(D, D, depth=3)` accidentally produces D→D→D
(see analysis §4.3). New `pillarLayerWide(D, hidden=2D, depth=3)` produces
D→2D→2D→D. Real expressiveness, ~2× pillar params.

### Gated ctx_agg

```text
delta   = img_seq.mean(dim=1)
gate    = sigmoid(ctx_gate_proj(ctx_agg))
ctx_agg = gate * ctx_agg + (1 - gate) * ctx_delta_proj(delta)
```

GRU-style. Stable magnitude across layers; early-layer info no longer washes
out.

### What stays the same

`ContextAttentionMixer` for the initial ctx_agg, `GatedContextInjection` per
layer, the spatial post-processing (`flow_predictor`, `context_final`, the
pooled context update onto first K tokens), the Bezier-combine at the end of
each block. Same-H/W batch fast path and per-sample mixed-H/W fallback kept.

### What is removed

`Embedding(1000, d_model)` time path, `text_embeddings + time_embed(t)` sum,
`pillar_cross_attn` and `norm_pillar`, the shared single `norm2` (split into
`norm2_q` and `norm2_kv`).

## Text encoder + per-token plumbing

```python
def forward(self, input_ids, attention_mask=None):
    outputs = self.language_model(input_ids=input_ids, attention_mask=attention_mask)
    last_hidden = outputs.last_hidden_state
    text_seq = self.ouput_layer(last_hidden)             # per-token (broadcasts)
    text_mask = attention_mask.bool() if attention_mask is not None \
        else torch.ones(text_seq.shape[:2], dtype=torch.bool, device=text_seq.device)
    return text_seq, text_mask
```

The `ouput_layer` chain broadcasts cleanly over `[B, T_txt, ·]` because
`nn.Linear` and `BezierActivation` both handle 3D inputs.

CFG null becomes the encoded empty prompt (`tokenize("")` -> `(input_ids, mask)`
-> precomputed `(null_text_seq, null_text_mask)`), not a zero vector. Closes
the train/test CFG gap.

Training datasets return `(image, input_ids, attention_mask)` rather than
preencoded pooled embeddings. The text encoder is called inside the train
step; the DistilBERT backbone can be frozen (existing param group split) or
embeddings cached per-prompt on disk to keep throughput.

Pipeline files updated:
`fluxflow-core/src/fluxflow/models/{pipeline,diffusion_pipeline}.py`,
`fluxflow-core/src/fluxflow/utils/visualization.py`, training datasets and
loops in `fluxflow-training`, ComfyUI `TextEncode`/`Sampler` nodes
(new `FLUXFLOW_TEXT` output type), one wiring update in `fluxflow-ui`.

## Training and losses

### New ctx shrinkage term

```text
L_ctx_shrink = alpha_ctx · E[ ||ctx_features||^2 ]
# measured on the pre-attention ctx_features at the bottleneck
```

Deterministic information regularizer: ctx only carries information that
reduces L_rec by more than `alpha_ctx · ||ctx||^2`. When z is sufficient,
ctx -> 0, SPADE contribution -> 0. Clean residual coupling.

### KL on z — unchanged formula, new dynamic range

```text
L_KL_z = -0.5 · sum(1 + logvar - mu^2 - exp(logvar))
```

With wide logvar, specific channels can shut noise off (logvar -> -8). KL
warm-up matters more; standard cosine warm-up over 10k steps to beta_KL=0.5.

### Loss composition per pipeline stage

Stage 1 (VAE warmup):
```text
L = L_rec(x, x_hat)
  + beta_KL(t)  · L_KL_z
  + alpha_ctx(t) · L_ctx_shrink     # warmup delayed to step 5000
```

Stage 2 (VAE + GAN):
```text
L_G = L_stage1 + lambda_GAN · L_adv + lambda_FM · L_feat_match
L_D = hinge loss + R1 penalty
```

Stage 3 (Flow, frozen VAE):
```text
L_flow = || v_pred - v_true ||^2
       (with cfg_dropout_prob = 0.10 substituting null_text_seq / null_text_mask)
```

### Discriminator

`PatchDiscriminator` unchanged (base_ch=32, depth=3, no spectral norm,
ctx_dim=0). The improved decoder output is automatically a harder target for
D — no D changes needed.

### Schedules

| Variable | Range | Schedule |
|---|---|---|
| `beta_KL` | 0 -> 0.5 | cosine over 10k steps |
| `alpha_ctx` | 0 -> 1e-3 | linear over 5k steps, starts at step 5k |
| `gamma_scale`, `beta_scale` (multi-scale SPADE) | 0 -> learned | learnable |
| `lambda_GAN` | 0 -> 1.0 | step-on at GAN stage start |
| `cfg_dropout_prob` | 0.10 | constant |

### New metrics

`ctx_norm`, `logvar_min/max/mean`, per-layer `gamma_scale` and `beta_scale`,
split `flow_loss_z` vs `flow_loss_ctx`.

### Config schema additions

```yaml
vae:
  loss:
    kl_z_weight: 0.5
    kl_z_warmup_steps: 10000
    ctx_shrinkage_weight: 0.001
    ctx_shrinkage_warmup_start_step: 5000
    ctx_shrinkage_warmup_steps: 5000
  arch:
    logvar_bezier_init: [-8.0, -2.0, 2.0, 4.0]
    multiscale_spade_dilation: 3
    ctx_attn_heads_min_head_dim: 16

flow:
  text:
    t_txt: 32
    null_prompt: ""
  arch:
    rope_2d: true
    time_embedding: "sinusoidal_continuous"
    pillar_hidden_mult: 2
    drop_pillar_cross_attn: true
```

## Testing strategy

Markers reused: `slow`, `gpu`, `integration`. One new marker
`compat_break` for tests that verify the redesign refuses to silently load
old v0.10.0 checkpoints.

TDD discipline applies: write the math unit tests first, then implement.

Coverage classes:

1. Math unit tests per new component (WideTrainableBezier range, 2D axial RoPE
   translation invariance, multi-scale SPADE identity at init, conditional
   ctx coupling, sinusoidal time, per-token text shape and CLS extraction,
   widened pillarLayer shape, mask-aware ParallelAttention, gated ctx_agg
   magnitude stability, dual FiLM independence).
2. Shape contract tests (VAE encode / decode shapes, Flow forward
   signature, pipeline e2e shape).
3. Identity / regression smoke tests (SPADE identity at init, no NaN forward
   and backward, CFG null prompt finite, old-checkpoint clear error).
4. Numerical sanity tests (single optimizer step decreases reconstruction
   loss, KL warm-up at step 0 and step 10000, ctx shrinkage warmup delay,
   logvar histogram has values < -3 after 1k steps).
5. Integration tests per package (fluxflow-core e2e, fluxflow-training
   per-stage, fluxflow-ui Flask + Selenium, fluxflow-comfyui node types).
6. Performance baselines on the reference GPU (no >25% throughput regression,
   peak GPU memory <= 24 GB at batch=1, 1024^2).

Selenium MCP per project conventions: reuse `SELENIUM_SHORTCUTS.md`, log new
shortcuts there.

## Done-criteria (gate to merge to develop)

All three measurable acceptance criteria must hold:

**(A) VAE quality at D=32.** Reconstruction LPIPS at D=32 on the validation
set is at most v0.10.0-pre's LPIPS at D=128, within 10%. Tests the
clean-Gaussian + conditional coupling + multi-scale SPADE delivery.

**(B) Flow text understanding.** Paired prompts differing by one qualitative
word (50 pairs) — CLIP text-image similarity for the correct pairing exceeds
the wrong pairing by >= 0.05 on average; v0.10.0-pre is <= 0.02 today.

**(C) Computational budget.** VAE forward+backward at 1024^2 at most 1.25×
v0.10.0-pre wall time. Same for Flow forward+backward with T_txt=32. Peak GPU
memory at batch=1, 1024^2 stays under 24 GB.

These are encoded as `@pytest.mark.acceptance` tests in
`fluxflow-training/tests/acceptance/`. Pass-gate for M9.

## Risks

- Wide logvar destabilizes training (giant KL). Mitigation: cosine warm-up,
  clip logvar gradients, fall back to upper=2.
- Multi-scale SPADE doubles decoder cost in practice. Mitigation: throughput
  tests gate M2; drop `beta_hi` if criterion C fails.
- Per-token text OOM on long prompts. Mitigation: T_txt=32 cap.
- Conditional ctx collapses to zero too aggressively. Mitigation: delayed
  alpha_ctx warm-up; monitor `ctx_norm`.
- CFG null behaves differently from null-zeros at inference quality.
  Mitigation: side-by-side eval in M8.
- Old checkpoints silently corrupt. Mitigation: `compat_break` tests assert
  failure mode with clear `IncompatibleCheckpointError`.
- 2D axial RoPE breaks variable-H/W batches. Mitigation: existing fast-path
  + per-sample fallback; mixed-batch tests.
- Per-token DistilBERT increases step time >25%. Mitigation: freeze backbone;
  cache encoded prompts.
- Dropping `pillar_cross_attn` loses unintended quality. Mitigation: M8
  ablation; restore as proper cross-attn over per-token text if needed.

## Rollback

Each milestone independently revertable on `feature/model-v0.10.0`. The
branch never reaches develop until M1–M9 are green. If done-criteria fail
after M8, tag `feature/model-v0.10.0-pre-redesign` on the commit before M1
and `git revert` the redesign commits.

## Salvage from existing checkpoints

`outputs/flux/flxflow_final.safetensors` (145.8 MB, 814 tensors, v0.10.0,
D=32) is the primary salvage source. Plus `outputs/flux/D_img.safetensors`
(2.8 MB) and `outputs/flux/text_encoder.safetensors` (283.9 MB).

Reuse percentages:

| Subsystem | Reused |
|---|---|
| Text encoder (DistilBERT backbone + ouput_layer projection) | 100% |
| Discriminator (PatchDiscriminator) | 100% |
| VAE compressor (conv stacks, projections, attention, norms) | ~90% |
| VAE expander (everything except SPADE heads which warm-start `beta_mid`) | ~75% |
| Flow processor (cross-attn, projections, norms; FiLM and pillars padded) | ~70% |
| **Overall** | **~80%** of params from `flxflow_final.safetensors` carry through |

Migration handled by `scripts/migrate_v0.10.0_to_redesign.py`:

- Direct-copy 100%-compatible keys
- Linear rescale of `logvar_activation` params from [-1,1] -> [-8,4]
- Partial-fill SPADE warm starts: old `mlp_shared` -> new shared MLP first
  conv; old `mlp_beta` -> new `beta_mid`; new `beta_low`, `beta_hi`,
  `gamma_raw`, `gamma_scale` zero-init
- Pad pillar layers: old `(D, D)` -> upper-left of new `(2D, D)`
- Duplicate FiLM: old per-pillar FiLM -> new `film_pX_text`; `film_pX_time`
  zero-init so the model preserves prior behaviour at init
- Duplicate norm2: old single `norm2` -> both new `norm2_q` and `norm2_kv`
- Drop dead keys (logged): `time_embed`, `pillar_cross_attn`, `norm_pillar`

The CLI emits a one-page report. A `test_salvage_loads_into_new_model` test
in §6 covers the round-trip.

### Order of operations for testing

1. Land M1–M4 (foundations + new modules)
2. Run salvage script -> `flxflow_v0.10.0_redesign_warmstart.safetensors`
3. Land M5 (training pipeline + losses)
4. Use `config-v0.10.0-redesign.yaml` pointing at the warm-start
5. Run Stage 1 ~5k steps — verify §5.6 metrics
6. Run Stage 2 — verify multi-scale SPADE γ/β scales activate
7. Run Stage 3 — verify per-token text changes outputs on paired prompts
8. M8 acceptance criteria checks

Warm-starting also reduces M8 cost ~2-4× vs from-scratch.

## Out of scope (deferred)

The analysis surfaced ~15 quality killers; this design addresses ~13.
Intentionally deferred:

- Replacing Bezier 5× channel fan-out with a depthwise variant. The 5× tax
  is real but absolute compute at D=32 is small. Revisit if criterion C
  fails.
- Decoder-side cross-attention from ctx to spatial features at high
  resolution. Multi-scale SPADE largely fills the role at a fraction of the
  parameter cost. Revisit if criterion A fails.
